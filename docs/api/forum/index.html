Forum topics #

Telegram allows creating forums with multiple distinct topics.¶

Bots can also make use of topics, if enabled through @botfather.¶

Group forums #

Forums may be created either by invoking channels.createChannel with the megagroup and forum flags set, or by converting an existing supergroup into a forum using channels.toggleForum with enabled=true.
If the group is a basic group, it should be upgraded to a supergroup before converting it into a forum.¶

Forums can also be converted back to supergroups using channels.toggleForum with enabled=false.¶

Note that the channels.toggleForum method can only be invoked by admins with owner rights.¶

Forums have the channel.forum flag set, and conversation happens in distinct forum topics.¶

Only users with manage_topics admin rights can create, modify and delete group forum topics.¶

Bots can also behave like forums if Threaded mode is enabled via @botfather, this mode is especially useful for AI chatbots ».¶

Note: this feature is subject to an additional fee for Telegram Star purchases as described in Section 6.2.6 of our Terms of Service for Bot Developers.¶

Bots with threaded mode enabled have the user.bot_forum_view flag set, and conversation happens in distinct forum topics.¶

The bot will be able to create, modify and delete bot forum topics » in chats with users, using the methods specified below ».¶

If the bot's user.bot_forum_can_manage_topics flag is set, users will also be able to create, modify and delete bot forum topics in their private chat with the bot as specified below: this flag is controlled by the "Disallow users to create new threads" option in @botfather.¶

Note: while the API always allows users to send topic-less messages (that end up in the "General" topic) regardless of the value of the bot's user.bot_forum_can_manage_topics, graphical clients should prevent users from sending topic-less messages if the bot's user.bot_forum_can_manage_topics flag is set: in this case, before sending/forwarding the message(s), a new topic must first be created by invoking messages.createForumTopic, and the messages should be sent to the newly created topic, instead.
In this case, the topic UI for the "General" topic should be replaced with the View as messages » UI, but should always show a "Type any message to create a new thread" bubble pinned to the bottom, letting the user know that sending a new message in the "General" topic will actually create a new topic and send that message there, instead.¶

On the other hand, if user.bot_forum_can_manage_topics is not set, users cannot create, modify and delete bot forum topics (doing so will emit an BOT_FORUM_CREATE_FORBIDDEN RPC error), and the client should allow sending messages to the "General" topic.¶

Forum topics #

forumTopic#fcdad815 flags:# my:flags.1?true closed:flags.2?true pinned:flags.3?true short:flags.5?true hidden:flags.6?true title_missing:flags.7?true id:int date:int peer:Peer title:string icon_color:int icon_emoji_id:flags.0?long top_message:int read_inbox_max_id:int read_outbox_max_id:int unread_count:int unread_mentions_count:int unread_reactions_count:int unread_poll_votes_count:int from_id:Peer notify_settings:PeerNotifySettings draft:flags.4?DraftMessage = ForumTopic;

Group forums and bot forums can have multiple topics where users may interact.¶

Topics have a name (title) and an icon: the icon can be a custom emoji specified by the icon_emoji_id, or a default chat icon if icon_emoji_id is not set, filled with the color specified in icon_color.
Topics can be temporarily closed, preventing further messages from being sent to the topic.
Additionally, (only) the "General" topic may also be hidden.¶

Note that Telegram Premium users can pass any custom emoji to icon_emoji_id, while other users can only use the custom emojis contained in the inputStickerSetEmojiDefaultTopicIcons emoji pack.
If the default chat icon is used, its color cannot be modified after creating the topic.¶

All of the topic modification methods specified above can only be invoked by users/bots with manage_topics admin rights (for group forums »), by bots (for bot forums »), or by any user (for bot forums » if the bot's user.bot_forum_can_manage_topics flag is set).¶

Topics can be created by using the messages.createForumTopic method, and may be modified with the messages.editForumTopic method: these actions will generate messageActionTopicCreate/messageActionTopicEdit service messages.¶

All topics except for the "General" topic can be deleted by invoking messages.deleteTopicHistory, with the topic ID.
For bot forums », this method may be invoked both by the bot and (if the bot's user.bot_forum_can_manage_topics flag is set) by the user chatting with the bot.¶

There is no dedicated update emitted when a topic is deleted; instead, topic deletion is propagated to clients (including bots) through two complementary mechanisms.¶

Firstly, deleting a topic deletes all of its messages, including the messageActionTopicCreate service message that created the topic (whose id is equal to the topic ID itself, see below »).
These deletions are delivered as ordinary message deletion updates: updateDeleteChannelMessages for group forums » (i.e. when the forum is a channel/supergroup), or updateDeleteMessages for bot forums » (i.e. when the forum is hosted in a private chat with a bot, and is thus identified by a user peer).
When the deleted message IDs contain the topic's root message (the message with id equal to the topic ID), clients and bots should treat the entire topic as deleted.¶

Secondly, when refreshing the state of one or more topics – for example after receiving the message deletion updates above, or after receiving an updatePinnedForumTopic for an unknown topic – clients fetch them again using messages.getForumTopicsByID: the response will contain a forumTopicDeleted constructor (instead of a forumTopic) for each topic that no longer exists, confirming the deletion.¶

Topics may be pinned or unpinned using messages.updatePinnedForumTopic, emitting updatePinnedForumTopic or updatePinnedForumTopics updates.
Use messages.reorderPinnedForumTopics to reorder pinned topics.
You can pin at most topics_pinned_limit topics per forum, as specified by the client configuration parameters ».¶

Messages and updates from forum topics will have the top_msg_id flag set and populated with the topic ID (except for the "General" topic).¶

Every forum has a non-deletable "General" topic, with id=1; other topics will have other IDs, equal to the messageActionTopicCreate service message that created the topic.¶

To send messages to the "General" topic, just use messages.sendMessage as usual, as if you were writing to a normal supergroup.
On the other hand, topics with id != 1 are just the message thread of the messageActionTopicCreate service message that created that topic.
This means that topics should be treated similarly to message threads by the client.
To send messages to these topics, pass the topic ID to the reply_to_msg_id parameter of inputReplyToMessage, passed to reply_to when invoking messages.sendMessage, messages.sendMedia et cetera.¶

To reply to messages within a topic, pass the ID of the message to reply to inputReplyToMessage.reply_to_msg_id, and, unless we're replying to a message in the "General" topic, pass the topic ID to inputReplyToMessage.top_msg_id.
Note that when replying to messages in a topic, the inputReplyToMessage.top_msg_id field must contain the topic ID if and only if we're replying to messages in forum topics different from the "General" topic (i.e. reply_to_msg_id is set and reply_to_msg_id != topicID and topicID != 1): this way, if the replied-to message is deleted before the method finishes execution, the value in this field will be used to send the message to the correct topic, instead of the "General" topic.
Also note that since message threads can't have nested message threads, topics (except for the "General" topic) also can't have message threads (so replies to messages within topics won't generate further message threads).¶

Users may also choose to display messages from all topics as if they were sent to a normal group, using a "View as messages" setting in the local client.

Only applicable to supergroup forums.¶

Supergroup forums can use either a tabbed or list-based UI for topic selection, according to the value of the channel.forum_tabs flag.¶

This flag can be toggled using channels.toggleForum, by passing enabled=true and tabs=true|false to enable or disable the tabbed UI.¶

Monoforums #

Monoforums are a special kind of forum, used to implement direct messages to channels.¶

While in the API they are sometimes called "monoforums", they actually share more similarities with the saved messages API: see here » for the full documentation on direct channel messages.¶
