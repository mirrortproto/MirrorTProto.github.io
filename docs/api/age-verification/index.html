Access to users, chats, channels and individual messages may be restricted for a variety of platforms and reasons through the restriction_reason field.¶

To check if any of the restriction reasons applies to us, filter the restrictionReason array in the restriction_reason field, keeping only reasons where both of the following conditions are true:¶

  1. For all platforms specified in restrictionReason.platform (which contains a concatenated list of one or more multiple platforms, separated by -):
    • restrictionReason.platform is equal to all (in this case, it will be the only platform) OR
    • At least one platform matches the current platform (hardcoded within the client based on the current platform, i.e. ios, android, wp, etc) OR
    • At least one platform matches any of the platforms specified in the restriction_add_platforms dynamic configuration parameter »
  2. restrictionReason.reason is not contained in the list of reasons specified in the ignore_restriction_reasons dynamic configuration parameter ».

Then, using the newly filtered restrictionReason list:¶

  • If at least one of the restrictionReason.reasons available after filtering is not equal to sensitive, access to the content must be completely restricted, showing the error specified in restrictionReason.text.¶

  • Otherwise (there will be only one reason and it is equal to sensitive):¶

    • If the need_age_video_verification » client configuration key is not set or equal to false, age verification is disabled and the content may be accessed, provided it's hidden behind a 18+ spoiler.¶

    • If the need_age_video_verification » client configuration key is equal to true, the content may only be accessed after age verification using the age verification Mini App (see below), initiated by clicking on the 18+ spoiler.
      If age verification succeeds, the content may be accessed, provided it's hidden behind a 18+ spoiler.¶

      Upon successful or unsuccessful verification, the mini app will emit a web_app_verify_age event, containing info about the detected age, and the server will toggle the value of need_age_video_verification » accordingly (see below).¶

      The following client configuration parameters » are used to implement age verification:¶

      • need_age_video_verification » - Specifies whether age verification is required in the current jurisdiction.
        This flag will also be set to false if the current jurisdiction requires age verification for restricted content, and the user has successfully passed it on another device, or on the current device.
      • verify_age_country » - Unique name for the country or region whose legislation required age verification.
      • verify_age_min » - Contains the minimum age required to view sensitive content
      • verify_age_bot_username » - Contains the username of the bot whose Main Mini App must be opened in order to proceed with age verification.
        Note: only during age verification, all permission requests from the age verification Mini App (camera, microphone, etc) should be unconditionally allowed, without user interaction (except when required by the OS); video and audio playback without user interaction should also be allowed unconditionally.
        Upon successful or unsuccessful verification, the mini app will emit a web_app_verify_age event, containing info about the detected age.
